## 产品决策

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 先用哪家视频供应商 | **Seedance 2.0 Fast** |
| 2 | 参考图代表什么 | **角色以及出现的元素**（`subject/style/first_frame/last_frame` 四角色仍保留，默认 `subject`） |
| 3 | 生成结果是否长期保存 | **不保存**，只留本次会话的临时地址/封面 |
| 4 | 默认时长/比例/分辨率 | **通用默认**（5s / 16:9 / 720p）；桌宠参数只作为测试案例 |
| 5 | 一个工作区还是三个子模式 | **只做一个** `/video/create` |
| 6 | 插件是否支持生成 | **不支持**，只保证提示词优化 |
| 7 | 视频结果是否评估 | **只做提示词评估**；视频结果人工看 |
| 8 | 生成前是否确认费用 | **要** |
| 9 | 最多几张参考图 | **4 张** |
| 10 | 是否需要音频/对白 | **不做**，只约束视频本身；适配器需标明模型是否默认带音频 |
| 11 | 提示词输出形态 | **`structured` + `compact` 两种，默认 `auto`**，结构化面板可折叠 |
| 12 | 结果体检范围 | **只做基础体检**（时长/分辨率/比例/音频/大小/URL 过期） |
| 13 | 桌宠动画怎么接 | **先不考虑**，只作为端到端测试案例 |

## 工程决策

| 项 | 结论 | 理由 |
| --- | --- | --- |
| 文档存放 | 过程记录放 `docs/archives/133-video-mode/`，结论进 `docs/architecture/` 与 `docs/developer/` | 沿用仓库既有的 archives 编号约定 |
| 视频字节 | 不进 IndexedDB、不进备份 | 避免重演数据库膨胀历史问题 |
| 自动重试 | 不做 | 按次计费，重试可能产生意外费用 |
| 参考图发送 | 按会话中的顺序映射为 `inputImages`，角色只用于提示词与 UI | 多数视频 API 只接受有序数组 |
| 模式真相源 | 路由决定模式，不在全局 store 另存可写副本 | 避免“标签是视频、页面是基础”一类错位 |
| 新会话 store 的 restore fallback | **必须用 `null`**，不能用默认对象 | CAS 基线必须等于存储原值；空库时默认对象会让首次保存被误判为跨窗口冲突 |
